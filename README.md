# voice_record — речь в текст через диктовку Claude Code

Отдельная копия той части VR-проекта (голосовая разработка в шлеме Quest), которая превращает
голос в текст, — без шлема, страницы, Vite и WebSocket. Аудио на входе, текст на выходе.

## Как это работает

1. В скрытом псевдотерминале (pywinpty) запускается настоящий интерактивный Claude Code
   (`claude`) с включённой встроенной голосовой диктовкой
   (`{"voice":{"enabled":true,"mode":"hold","autoSubmit":false}}`, только для этого запуска,
   через `--settings`). Сессия всегда новая, рабочая папка — пустая `.state\claude-cwd`, так что
   ничей `CLAUDE.md` проекта не подгружается. Этот Claude ничего не выполняет: из его строки ввода
   только читается текст.
2. «Нажатие»: в терминал каждые 33 мс пишется пробел (так выглядит зажатая клавиша), микрофоном
   Windows по умолчанию временно становится виртуальный `Microphone (Steam Streaming Microphone)`,
   а звук проигрывается в его «динамик» `Speakers (Steam Streaming Microphone)` (WASAPI exclusive,
   48 кГц, стерео float32, −30 дБ: драйвер добавляет +30 дБ). Звук, пришедший до надписи
   `listening…`, придерживается, чтобы не потерять первые слова.
3. «Отпускание»: доигрывается остаток, пробел перестаёт «держаться», микрофон по умолчанию
   возвращается прежний.
4. Экран терминала эмулирует `pyte`; из рамки строки ввода (между линиями `─`) берётся текст до
   курсора (порт `extractDraft` из `web/src/draft.js`). Текст считается готовым, когда пропала
   надпись `Transcribing…` и он не меняется 0,5 с. Затем строка ввода очищается (Ctrl+U ×20).

## Что нужно

- Windows, Python 3.12 (`.venv` уже создан в этой папке).
- Claude Code CLI (`claude` в PATH) с рабочей голосовой диктовкой — вход через аккаунт claude.ai.
- Драйвер **Steam Streaming Microphone** (ставится со Steam; проект VR уже им пользуется).

Настройки: скопируйте `config.example.json` в `config.json` и при необходимости поправьте
(имена устройств, усиление, модель скрытого Claude). Свой `config.json` в репозиторий не
попадает; пока его нет, берётся `config.example.json`.

Установка зависимостей заново (если нужно):

```
py -3.12 -m venv .venv
.venv\Scripts\python -m pip install -r requirements.txt
```

Команду `python` из PATH не используйте — только `.venv\Scripts\python`.

## Запуск

```
# WAV-файлы (любая частота и число каналов): печатает текст каждого
.venv\Scripts\python -m voice_record phrase.wav another.wav

# свой микрофон: Enter — начать, Enter — закончить, q — выход
.venv\Scripts\python -m voice_record --mic
.venv\Scripts\python -m voice_record --mic --device "<имя микрофона>"

# сырой PCM s16le моно 48 кГц со стандартного входа
.venv\Scripts\python -m voice_record --stdin < audio.pcm

# -v — подробный журнал (время запуска, распознавания) в stderr
```

`--mic` открывает настоящий микрофон заранее, по имени, до переключения устройства по
умолчанию. Если микрофоном по умолчанию в Windows уже стоит сам виртуальный Steam-микрофон,
укажите настоящий через `--device` (программа подскажет список).

Тестовая фраза синтезатором речи Windows:

```
.venv\Scripts\python scripts\say_to_wav.py "Привет, это проверка" test.wav
.venv\Scripts\python -m voice_record test.wav
```

## Из Python

```python
import asyncio
from voice_record import VoiceToText, load_wav

async def main():
    async with VoiceToText() as vt:              # запускает скрытый Claude Code (~3 с)
        print(await vt.transcribe(load_wav("phrase.wav")))
        # или поток: async-итератор кусков PCM s16le моно 48 кГц
        # print(await vt.transcribe(chunks()))

asyncio.run(main())
```

`transcribe` принимает `bytes` (PCM s16le моно 48 кГц) или асинхронный итератор таких кусков;
`load_wav` и `to_pcm48k` приводят звук к этому формату.

## Важно

- Пока идёт запись, **микрофон Windows по умолчанию временно переключён** на виртуальный.
  Прежний возвращается сразу после фразы, при выходе и даже после аварийного завершения (при
  следующем запуске, из `.state\default-mic.json`).
- **Не запускайте одновременно с диктовкой VR-моста** (`npm start` в VR-проекте): оба
  пользуются одним виртуальным микрофоном и оба переключают микрофон по умолчанию. Просто
  запущенный мост не мешает, пока в шлеме никто не диктует.
- Распознавание идёт в реальном времени: фраза в 6 с занимает около 9 с (звук + ~3 с на
  дораспознавание и паузу «текст устоялся»). Запуск скрытого Claude Code — ~3 с, один раз.
- При первом запуске скрытый Claude Code спрашивает, доверять ли папке; программа сама выбирает
  «Yes, I trust this folder» — только для своей пустой рабочей папки `.state\claude-cwd`.
- `.state\` — служебная папка (настройки скрытого Claude, его рабочая папка, сохранённый микрофон).

## Файлы

- `voice_record/core.py` — `VoiceToText`: запуск, `transcribe`, ожидание и чтение текста.
- `voice_record/claude_pty.py` — скрытый Claude Code в псевдотерминале, детектор `listening…`.
- `voice_record/dictation.py` — «зажатие» пробела и подача звука, все ожидания с крайним сроком.
- `voice_record/virtual_mic.py` — проигрывание в виртуальный микрофон.
- `voice_record/audio_devices.py` — переключение и возврат микрофона по умолчанию (pycaw).
- `voice_record/screen.py` — экран терминала (pyte) и извлечение набранного текста.
- `voice_record/audio.py` — чтение WAV, пересчёт в 48 кГц моно.
- `voice_record/__main__.py` — командная строка.
- `scripts/say_to_wav.py` — тестовая фраза синтезатором речи Windows.
